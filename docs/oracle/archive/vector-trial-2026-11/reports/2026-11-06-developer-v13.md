- "One variant per transaction" could not be met exactly: see Challenges.

## Challenges to locked decisions
- none to locked decisions. Gap against the Developer standard "multi-row writes in one transaction": the hosted database offers only per-request writes with the service key (no database password in the env files, no loader function, and new functions need the Architect). The loader writes a batch of variants, then their pieces, both as upserts. A failure mid-way could leave a variant without all its pieces until a re-run, which is safe. After the load the check found no such variant. If the Architect wants strict atomicity, a small "load one combo" function would be needed.
