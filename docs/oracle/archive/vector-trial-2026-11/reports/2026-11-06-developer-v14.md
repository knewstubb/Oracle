The 0.3/0.3/0.4 build-plus-deck blend is not implemented (§5.6 only).
- The owner's Archidekt deck (Wilhelt for W1 and W2, Mendicant for M1) is used only as the exclusion list, mainboard only. Maybeboard cards stay eligible.
- Seed picks are removed from all four arms so every arm shares one candidate set (contract §4B.2 says to remove them from the candidate list; it is silent on the baselines). The picks are listed per list in the JSON.
- Seed pick eligibility follows the contract exactly (synergy > 0, legal, in colour, not the commander); it does not exclude basics or deck cards, since those are removed later as candidates.
- Arm names follow the task (F1, F2, V, FUSED); the contract calls them B1, B2, V, F2. Same content.
- Unknown synergy (exactly 0 with an inclusion, or null) uses its inclusion rank in the F2 order and in fusion, and is shown as null, never 0. Cards with no EDHREC data keep null and add nothing to the EDHREC term.
- Fusion candidates are the vector top 200 plus the filtered EDHREC cards; a missing rank contributes 0. Ties: score, vector rank, EDHREC rank, name.
- A card counts as legal if any printing row says legal (same as the SQL function); identity comes from the printing row. Basic = type line contains "Basic".
- Commander-level (no build) comparator lists for §5.8 and the tagged arms are not produced (not in this task).
