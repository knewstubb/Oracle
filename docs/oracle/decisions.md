# Oracle — locked decisions register

Locked means: build on it, don't relitigate it. To change one, an agent raises a challenge in its report; only the owner can unlock. The Orchestrator records changes here after approval.

## Data model
- **D-001** Three core tables: `user_cards`, `user_copies`, `deck_cards`. Proxies are `user_copies` rows with `is_proxy = true`, not a separate table. *(Updated 2026-09-25: owner chose the `user_` prefix to match the deployed schema and avoid a wide rename refactor.)*
- **D-002** Deck readiness has exactly three owner-facing states: **Draft / Assembling / Playable**. For Commander, the simple complete-list rule is exactly 100 cards including the commander(s), with a commander selected; Maybeboard does not count. A list that does not meet that rule is Draft. A complete list with any required slot Unsleeved is Assembling; a complete list with every required slot Sleeved is Playable, using originals and/or proxies, with generic basic lands automatically counting as Sleeved under D-032. There is no manual "still designing" override solely to keep a full list Draft. This is Oracle's simple list-completeness and readiness rule, not a replacement for separate detailed MTG legality information. Other supported formats retain their appropriate size rules; do not assume all formats use 100 cards. *(Owner-approved replacement on 2026-09-29 for the earlier Brew / Boxed / Archived scheme; updated after U1 feedback to include the generic-land exception. Implementation pending. There is no retired-deck concept for now; see D-029.)*
- **D-003** `scryfall_id` (printing) and `oracle_id` (canonical card) are never interchangeable. Resolution functions are discrete and unit-tested.
- **D-004** Finish (`nonfoil` / `foil` / `etched`) is an independent attribute on the physical copy. *(Updated 2026-09-25: owner chose `nonfoil` as the common term.)*
- **D-005** Maybeboard is modelled as a separate `deck_cards` relation. Moving a Sleeved card to Maybeboard releases its assigned physical copy to storage; Maybeboard membership does not reserve that copy or count towards main-deck readiness. *(Release behaviour owner-approved in B3 feedback, 2026-09-29.)*
- **D-006** Clean slate beats complex migration: when the schema changes significantly, prefer flush-and-rebuild over a convoluted migration (owner approval required each time).

## Allocation
- **D-007** The destructive clear-and-recompute Allocation Resolver is retired as a write path. Its compute layer is reused as a suggestion engine that proposes allocations without writing them.
- **D-025** Card placement is **Sleeved / Unsleeved**, not Considering or owner-facing Planned. A physical copy is **Original / Proxy**. Owner-facing availability labels are **Available / Unavailable / Alt available / Proxy available / Unowned**. For an ordinary Unsleeved slot, the headline preference is a free requested original (Available), then a free alternate original (Alt available), then a free proxy (Proxy available); retain every other usable option in the action choices. If no eligible copy is free but copies are owned, show Unavailable with the reason/source; Unowned means neither an original nor proxy is owned. Placement, copy type, and availability are separate facts; an Unsleeved slot does not itself create or reserve a physical copy. Preserve separate Maybeboard membership under D-005 and the generic-land exception D-032. Existing excluded-copy eligibility remains subject to D-028's transition gate. *(Owner direction and B1 feedback approved 2026-09-29; existing internal names need not be renamed merely to change display language.)*
- **D-026** **Proxy** is both a copy type and an action. The **Proxy action creates a new physical proxy in the collection and sleeves it into the selected deck slot**; it is not a plan/print-queue state. **Proxy available** refers to an existing free proxy that can be sleeved without creating another copy. Do not conflate those two operations or silently change an original copy into a proxy. *(Owner-approved 2026-09-29.)*
- **D-027** The separate shortage list highlights **shortfalls in owned original copies across deck requirements**, helping the owner see proxy usage and decide whether to obtain more originals. Proxies, whether free or Sleeved, do **not** cancel an original-copy shortfall. Include requirements currently filled by Sleeved proxies, not only Unsleeved requests; otherwise fully Playable proxy-heavy decks would disappear from the view. Show originals owned, proxies actually sleeved, affected decks and additional originals needed, accounting for usable originals already owned before suggesting more. Example: two decks need Sol Ring, with one original and one proxy; there is still an original shortfall of one even if both decks are Playable. Show shortages only, not every harmless overlap; generic basics are exempt under D-032. The list is informational and must not change deck lists, assignments, readiness, or add deck-level conflict badges. A purchase or view of the list does not automatically replace a sleeved proxy or allocate copies. Preserve explicit placement, copy uniqueness and import reconciliation. *(Owner-approved clarification of U3 on 2026-09-29; the earlier proxy-offset question is resolved. Detailed presentation and matching remain contract/spec work.)*
- **D-028** Retire the **Missing** concept from the owner-facing product for now, including its actions and state/filter presentation. This is not approval to delete copy records, drop stored fields, discard assignments/history, or automatically make previously excluded copies available. Inspect the existing representation and obtain approval for its transition before changing existing-copy eligibility or stored data. *(Owner-approved removal direction 2026-09-29; transition and implementation pending. Owner re-confirmed "remove Missing for now" on 2026-10-10; the treatment of copies already marked Missing is still an open owner question.)*
- **D-029** There is **no retired/archived deck concept for now**: no retired folder, no Archive/Unarchive action and no fourth deck state. Every deck counts the same everywhere, including original-copy shortages (D-037). **Break down** remains the separate action that releases a deck's physical copies while retaining its list. *(Owner-approved 2026-09-29 as a retired folder; changed by the owner on 2026-10-10 to "remove the retired concept for now". Legacy "Graveyard" labels still present in the app are to be removed.)*
- **D-030** Loading, failed, or stale availability/readiness data must be presented explicitly. A failed lookup must not be translated into **Unowned**, an empty successful reconciliation, or **Playable**. Show usable primary content before secondary prices/analysis; use appropriately scoped spinners and skeletons shaped to match the content being loaded. Pick-list copy locations, copy identity/type, and action eligibility are essential assembly information, not optional secondary enrichment. *(Owner-confirmed 2026-09-29, including P3 feedback.)*
- **D-037** The **Reconcile page is the original-copy shortage view** described in D-027. It counts **original copies only** as supply; proxies never cancel demand. Every main-deck slot for the card counts as demand, including slots filled by a Sleeved proxy. Example: Sol Ring is in three decks, with one original and two proxies, so Reconcile shows Sol Ring as short by two originals. All decks count (D-029). Generic basics stay excluded (D-032). This replaces the 2026-10-05 Reconcile v1 rule that proxy-filled slots add no demand. *(Owner-approved 2026-10-10. Still open: whether cards with no original owned at all appear, and whether matching is per printing.)*
- **D-038** The **Proxy action records the printing the deck slot asks for**. For example, a proxy made for a deck's Borderless Sol Ring is recorded as that printing. *(Owner-approved 2026-10-10; resolves T-28 G-M3.)*
- **D-039** **Any physical copy removed from a deck list returns to storage.** This applies to removing a card, moving it to Maybeboard (D-005) and switching a tracked basic land to generic (D-032). The deck's list total stays as the list says; only the physical copy moves. *(Owner-approved 2026-10-10; resolves T-28 G-D2/G-D3. Single and batch card removal already release to default storage [Confirmed: src/app/api/decks/[id]/cards/[cardId]/route.ts, src/app/api/decks/[id]/cards/batch/route.ts].)*
- **D-032** **Generic basic lands are automatically considered Sleeved** for display and deck readiness. They require no physical-copy assignment or manual sleeving confirmation and do not create owned originals/proxies, reserve inventory, or enter the outstanding pick list or original-shortage demand. This is a deliberate exception for generic basic lands only; specifically tracked basic-land copies retain normal assignment and availability behaviour. Main-list generic land quantities still count towards the format's deck size, while Maybeboard does not. *(Owner-approved U1 replacement for the earlier physical-confirmation proposal, 2026-09-29.)*
- **D-033** The **pick list is a primary assembly screen**: for each outstanding card it must show where eligible physical copies are, including their storage location or source deck, and distinguish originals, proxies, and relevant printing/finish details. Use the same **Sleeve**, **Move from [deck] / Move to [deck]**, and **Proxy** meanings as other screens. A transfer is an explicit physical move, not a reservation or removal of the source deck's list entry; show its effect before confirmation and update both decks afterwards. Do not infer a location when it is not recorded. Generic basics are already covered under D-032 and must not be presented as cards still needing to be pulled. *(Owner-approved B2 and pick-list emphasis, 2026-09-29.)*

## Brew Canvas
- **D-008** Free-drag with snap-to-grid at launch.
- **D-009** Drag-to-assign is the single placement mechanic. Every placement carries a `source` parameter (e.g. `manual`, `ai`) so undo, validation and audit logging are shared across manual and AI placement.
- **D-010** Secondary category is shown as a badge.
- **D-011** No phase gates on conversation in Brew mode. Commit lives on the candidate card itself; candidates and committed cards are different visual object types.

## Visual language and accessibility
- **D-012** Ownership state is encoded with colour plus a label or icon, never colour alone (WCAG 1.4.1).
- **D-013** Status hues stay outside the WUBRG palette so they never read as mana identity.
- **D-014** Quiet default, loud exception: the normal owned state is visually quiet; proxy, over-allocated and unowned states carry the visual weight.
- **D-015** Controls sit visually inside the scope they act on (object-action mapping). Dashed borders mean empty drop zones, never clickable actions.

## AI features
- **D-016** Structured data from LLMs comes via tool use or a JSON sidecar block. No regex parsing of prose.
- **D-017** Category-count vs curve-target conflict (EDHREC archetype data vs Karsten CMC maths) is handled with cross-referenced warning messages, not a full category-by-CMC target matrix.
- **D-034** The advisor may **change a deck directly, without an explicit confirmation step**, but **every AI change must be undoable**. Each change is recorded with `source = 'ai'` (D-009) so undo and audit work the same way for AI and manual changes. Undo for AI changes is therefore needed in M2, not deferred to M3. *(Owner-approved 2026-10-10; answers T-15 O1 and differs from the contract's read-only recommendation. Today the sidebar assistant applies changes with no undo [Confirmed: src/contexts/OracleContext.tsx].)*
- **D-035** For now, advisor "buy" prices use **Scryfall prices, clearly labelled as estimates**. Card Kingdom pricing is deferred. *(Owner-approved 2026-10-10; answers T-15 O5 and amends the M2 roadmap wording.)*
- **D-036** Advisor defaults: (a) if an Upgrade refresh fails, keep the previous suggestions and say the refresh was unavailable; (b) ask before including an infinite-combo package when the owner's preference is unknown; (c) when evidence is thin, give fewer suggestions, each explained, rather than padding with generic staples. *(Owner-approved 2026-10-10; answers T-15 O2–O4.)*

## Import and collection parity
- **D-018** Archidekt maybeboard and sideboard cards are both imported into Oracle's maybeboard relation (`deck_cards` with the maybeboard relation per D-005). *(Locked 2026-09-26 after T-13 M1 exit test.)*
- **D-019** Archidekt proxy labels are **not** automatically honoured during built-deck import. Proxy status is set manually in Oracle. *(Locked 2026-09-26 after T-13 M1 exit test.)*
- **D-020** Import does **not** run an automatic allocation pass. Unassigned `deck_cards` slots remain planned until the user explicitly assigns them. *(Locked 2026-09-26 after T-13 M1 exit test.)*
- **D-021** Copy assignments must match the exact printing (`scryfall_id`) when possible. Instance-level accuracy is a core concept: the app must know exactly which tracked physical copy is in which deck. Generic basic-land slots have the explicit no-assignment readiness exception in D-032; this does not create fictional physical copies or weaken tracking for other cards. *(Locked 2026-09-26 after T-13 M1 exit test; generic-slot exception clarified after owner approval on 2026-09-29.)*
- **D-022** In `new_cards` import mode, maybeboard and sideboard cards are imported as planned maybeboard slots only. They do **not** create `user_copies` rows. *(Locked 2026-09-26 after T-20 review.)*
- **D-023** Basic lands are treated as fungible during import: any owned basic land of the same name can fill a basic-land slot, regardless of the specific printing listed in the source deck. Exact-printing matching does not apply to basic lands. *(Locked 2026-09-26 after T-21 review.)*
- **D-024** Import allocation conflicts include a `printing_mismatch` reason when a card is owned but not in the exact printing requested by the imported deck. *(Locked 2026-09-26 after T-21 review.)*
- **D-031** Deck import asks whether the deck is **Sleeved / Unsleeved**, rather than using Built/Draft or Theorycrafted to describe physical state. Unsleeved imports do not assign physical copies; their resulting readiness follows D-002, so a complete list with ordinary Unsleeved slots is Assembling, not automatically Draft. Generic basic lands still automatically count as Sleeved under D-032 without allocating copies. A Sleeved choice still requires actual copy reconciliation for tracked slots before it can establish Playable. Apply the same meaning to standalone and onboarding/batch imports. Preserve the separate explicit inventory effect of `new_cards` mode and D-018 through D-024; the new selector does not authorise duplicate inventory or a new automatic allocation policy. *(Owner direction approved 2026-09-29; generic-land exception incorporated after U1 feedback. Import spec and implementation pending.)*
