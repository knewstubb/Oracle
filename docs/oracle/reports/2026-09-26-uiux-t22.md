# Report: T-22 — Design the redesigned import reconciliation flow
Role: UX/UI
Status: DONE
Task as received: Read docs/oracle/specs/import-reconciliation-redesign-requirements.md and produce a UX spec plus HTML mockup for owner review.

## Changed files
- `docs/oracle/specs/import-reconciliation-redesign.md` — UX spec covering the tabbed layout, state-based conflict resolution, wishlist behaviour, printing hover/previews, alternate-printing selector, and persistence behaviour.
- `docs/oracle/mockups/import-reconciliation-redesign.html` — interactive HTML mockup showing the three tabs, deck expansion, state selectors, hover previews, alternate-printing control, and wishlist checkbox.

## New decisions made (need owner confirmation)
- The sub-state label for a Planned card whose copy is already sleeved in another deck is `Planned (used elsewhere)`.
- Tab counts are per unresolved deck-card instance.
- Alternate-printing availability is surfaced as an inline dropdown, not a modal.
- Wishlist cards show small deck-name tags under the card name so the user can see which decks the entry came from.
- Resolved rows stay in place and change to a subtle green-tinted background; they are removed only on a full page reload.

## Assumptions
- The mockup uses placeholder Scryfall IDs for cards that do not have a real `scryfall_id`; production will use the actual imported printing IDs.
- The hover preview will reuse the existing `CardHoverPreview` component already in the codebase [Confirmed: src/components/CardHoverPreview.tsx].
- The existing skeleton/empty-state patterns from `PicklistV2` and `DeckImportProgressList` can be reused for loading and empty states [Confirmed: src/components/PicklistV2.tsx, src/components/DeckImportProgressList.tsx].

## Challenges to locked decisions
- None.

## Open questions
- Should tab counts use a different unit (e.g. per unique card) to feel less alarming when one card appears in many decks?
- Should Resolved rows be collapsible into a separate "Resolved" section instead of staying inline?
- Should the wishlist deck tags be clickable to jump to the relevant deck in the Decks tab?
- Should alternate-printing conflicts block the finish action, or only warn?
