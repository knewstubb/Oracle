## Remaining type errors (39, all real defects)

The 39 errors group into 13 defects. Each entry gives file:line, what a user would see, and a suggested fix. None were fixed because each would change runtime behaviour (the task says list real bugs rather than guess a fix).

1. **Commander search filters on columns that don't exist** — `src/app/api/commanders/search/route.ts:130,143,162`.
   `ref_commander_taxonomy` only has `id, commander_id, taxonomy_slug, relevance, source, confidence, created_at` (migration `20260803100000_create_ref_taxonomy.sql:30`); the query filters `tag_type`/`tag_value` and orders by `deck_count`, which aren't columns. User sees: choosing an archetype/theme/tribe in commander search errors or returns nothing.
   Fix: join `ref_taxonomy` on `taxonomy_slug` and filter its `category`/`display_name`; drop the `deck_count` ordering (Architect/Developer).

2. **Auto-naming a chat always fails** — `src/app/api/oracle/sessions/[id]/generate-name/route.ts:120`.
   Calls `adapter.generateText(...)`, but `ProviderAdapter` only defines `sendMessage`/`sendMessageStreaming` (`src/lib/provider-adapter.ts:95-119`). User sees: a new Oracle chat is never auto-named (the request silently returns "AI generation failed").
   Fix: call `adapter.sendMessage({...})` and read its text, or add a small `generateText` helper to the adapter.

3. **Deck health pills do nothing** — `src/app/decks/[id]/page.tsx:356`.
   `<HealthStrip deckId={...} />` omits the required `onPillClick`, though `handlePillClick` already exists at line 159 and is never used. User sees: tapping a health pill at the bottom of a deck has no effect (should switch to the Cards tab and scroll to that category).
   Fix: pass `onPillClick={handlePillClick}`.

4. **Old brew / new-deck screen (paused Phase 8/9)** — `src/app/new-deck/page.tsx` (8 errors).
   - `116,119,124` — reads `session.committedCommander`; `BrewSessionState` stores `commander`. User: after choosing a commander the Oracle side panel never switches to "workbench".
   - `310` — `params` is not in scope (the local is `searchParams`). User: opening the brew page from a commander link ignores the commander.
   - `769` — `chatHandleRef` is not defined. User: "Discuss this card" throws; the chat input is not pre-filled.
   - `810,994` — writes `ownership_status: 'unknown'`, which is not one of `original | proxy | not_owned | generic` (D-001/D-012). User: cards added by chat show a broken/blank ownership badge.
   - `1155` — passes `handleCommitCommander` (takes a commander object) to `onSelectCommander` (takes a name string); the correct handler is `handleCommitCommanderFromChat`. User: choosing a commander from the card detail modal misbehaves.
   Fix: apply these when Phase 8/9 resumes. Not changed now.

5. **Colour-identity selected ring is never coloured** — `src/components/ColorIdentityFilter.tsx:103`.
   `style={{ ringColor }}` is not a CSS property (Tailwind ring colour is a CSS variable). User: selected colour pips show the default ring colour instead of their colour.
   Fix: set the CSS variable, e.g. `style={{ '--tw-ring-color': color.ring }}`, or apply a per-colour ring class.

6. **Commander suggestion images never load** — `src/components/CommanderSuggestionCard.tsx:45,46`.
   Reads `info.imageUrl`, but `getCardInfo()` returns only `{ scryfallId, canBeCommander }` (`src/components/CardHoverPreview.tsx:388-391`). User: suggestion cards show "No image".
   Fix: build the Scryfall image URL from `info.scryfallId` (same pattern as `CardImage`).

7. **Cards added via deck chat lose their card data** — `src/components/DeckChatTab.tsx:53,54`.
   `toBrewDeckCard` sets `mana_cost`/`mana_value` (not fields on `DeckCard`) and omits `cmc`/`type_line`/`oracle_text`, which are required and read by the canvas, curve and tooltip. User: cards added through deck chat show no mana value, type line or rules text.
   Fix: source `cmc`/`type_line`/`oracle_text` (e.g. from the card definition) and set those fields.

8. **`asChild` is ignored by the base-ui wrappers** — `src/components/DeckPickerPopover.tsx:63`; `src/components/TopNav.tsx:160,255`.
   These UI wrappers are base-ui, which uses `render={...}` rather than `asChild` (see `src/components/ui/popover.tsx:12` and `src/components/ui/dropdown-menu.tsx:95-116`). User: the deck-picker trigger and the Tools/avatar menu items render the wrong element (e.g. a button nested in a button) instead of the intended link.
   Fix: use the wrapper's `render={<Link ... />}` instead of `asChild`.

9. **Suggested commander images never load** — `src/components/explore/SuggestedCommanders.tsx:124`.
   `CardImage` requires `scryfallId` + `alt`; the component passes a bogus `cardName` and no id. User: Oracle-suggested commander cards show "No image".
   Fix: plumb a scryfall id (the `SuggestedCommander` type carries `artUrl`, not an id) and pass `scryfallId`/`alt`.

10. **Pick list shows wrong locations/thumbnails and no previews** — `src/components/PicklistV2.tsx:83,100,374,412,536`.
    Uses retired field names `storageLocationName`/`scryfallPrintingId` (the supply entry has `locationName`/`printingId`), `assignedTo.deckStatus` (only `isActive` is populated), and a non-existent `previewProps` from `useCardHoverPreview` (which returns only `triggerProps`). User: storage groups show "Unsorted", thumbnails are missing, hover previews don't show, and the claimed-deck status is never displayed.
    Fix: use `entry.locationName`/`entry.printingId`/`assignedTo.isActive`, and switch the hover preview to the hook's `triggerProps` pattern used elsewhere.

11. **Status-chip actions misbehave** — `src/components/StatusChipPopover.tsx:142,340,434,533,536,593,601,626,649`.
    Reads `tier4Confirm.deckName` (state field is `holderDeckName`); passes `validDecks` shaped `{isActive}` into `DeckPickerPopover` which expects `{deckStatus}`; reads `holder.deckStatus` (holders have `isActive`), so the Tier-3 instant claim never triggers; destructures `previewProps` and references `previewUrl`, neither of which exists, breaking the proxy hover/download/copy.

    Fix: use `holderDeckName`/`isActive`, and rework `CopyRow` to use the `useCardHoverPreview` hook's `triggerProps` with a real preview URL.

12. **Version-history restore cannot be cancelled** — `src/components/VersionHistoryPanel.tsx:267`.
    Passes `onOpenChange`/`variant` (not props of `ConfirmationModal`) and omits the required `onCancel`. User: on "Restore Version?" the Cancel button and Escape/backdrop dismiss do nothing.
    Fix: pass `onCancel={() => setRestoreTarget(null)}` and remove `onOpenChange`/`variant`.
